# 独立文生视频模型：首轮实际训练记录

日期：2026-11-27。此记录对应实际 CPU 执行与实际神经网络采样。

## 已完成的结果

独立模型 `text_video_flow_v1` 已实现并完成三阶段训练：从随机初始化开始预训练 800 步，继续自身 checkpoint 监督训练 800 步，再以新配置、独立输出目录继续 4,800 步。总计 **6,400 次 AdamW 更新**。三个阶段使用同一套程序生成开发语料和同一目标函数，续训阶段重建优化器；没有使用外部模型权重，也没有开展 RL 或 RLHF。

模型为 **354,956 参数**，16×16 RGB，4 帧，8 fps；每段输出 0.5 秒。视频和文字网络均本地初始化。训练集 256 个独立 episode，验证集 32 个，测试集 32 个。训练每步有放回抽取 8 段视频，总计 51,200 次片段呈现。

| 阶段 | 本阶段更新 | 累计更新 | 固定噪声验证总损失 | 训练/验证/保存阶段记录耗时 |
| --- | ---: | ---: | ---: | ---: |
| 初始化 | 0 | 0 | 1.17008206 | — |
| 从零预训练 | 800 | 800 | 0.13134741 | 33.96 秒 |
| 自身监督续训 | 800 | 1,600 | 0.10606102 | 36.16 秒 |
| 扩展监督续训 | 4,800 | 6,400 | 0.07285796 | 201.22 秒 |

三个阶段均按验证损失选择到本阶段最后一步。上述耗时合计 271.34 秒，不包含本次工程开发、依赖安装和所有前后处理，不是学校 GPU 时间估算。

在全部训练和 checkpoint 选择完成后，对独立的 32 个 test episode 评估一次最终选中权重：

| 指标 | 结果 |
| --- | ---: |
| 固定噪声 flow loss | 0.06276825 |
| 相邻帧过程监督 loss | 0.00881598 |

这是有参考监督任务的数值结果，不能换算为画质、文字理解或物理一致性评分。

## 实际生成效果

三个阶段均使用同样的前三条提示词、同样的初始噪声 seed 101、40 步 Heun、CFG 2.0。最终阶段增加第四条同物体反方向提示，观察文字变化。所有样本都是直接从高斯噪声积分得到，采样不读取训练或测试参考片段。

1. `A red sphere moves from left to right on a tiled floor.`
2. `A blue cube moves toward the camera on a tiled floor.`
3. `A green cone moves from left to right behind a gray pillar.`
4. `A red sphere moves from right to left on a tiled floor.`

人工查看准确像素的结论：初始 800 步主要出现背景和地面分层；延长到累计 6,400 步后，这组相同噪声样本的红、蓝、绿条件出现相应颜色区域，噪点减少。物体轮廓仍模糊，球/立方体/圆锥身份不稳定，左右运动指令也没有呈现可靠的方向控制。已经观察到文字颜色条件的响应，尚不能把这一组样本外推为通用语义或动作能力。

预览只做最近邻放大。原始 MP4 经解码核验为 `[4,16,16,3]`；NPZ 保留编码前 uint8 RGB 像素。没有超分、修图、替换帧或筛掉失败阶段。

## 验证与学校入口

本地 **129 项测试通过**；同一独立测试集在 [GitHub Actions 46059875318](https://github.com/billlza/isac-world-model/actions/runs/46059875318) 上实际 **129 passed**。其中包括真实梯度、数据与跨阶段 split 隔离、非均匀权重累积、优化器/RNG 的真实中断恢复、checkpoint 原子发布与故障注入、提交器防重复及失败状态。完整 CPU CLI 训练、采样和测试评估也已实际执行。

这次另准备了 17,193,264 参数、64×64、8 帧的单 H200 配置：100 步首测、20,000 步预训练、5,000 步监督续训。脚本绑定完整 commit、数据、配置与初始化权重，验证已记录的学校 Python/CUDA runtime 和实际 GPU 前反向执行。

**本次未向 Hamilton 提交作业，学校新模型吞吐、显存峰值和媒体依赖尚未实测。** 当前执行环境为 CPU，且没有可用的学校执行会话。一次本地 launcher 预检查因其禁用 user-site 后找不到本地安装的 Torch 而明确失败，未产生 scheduler claim；这不影响上述实际 CPU 训练，也不替代学校 module 检查。HPC wrapper 当前只提交新任务，trainer 自身支持严格原预算恢复。

下一次实际扩大实验时，应使用已准备的 H200 100 步配置记录资源和采样，再运行声明过的完整预算。当前三阶段保留了原训练方法中的从零初始化、复杂场景、参考可信度、过程监督与分阶段证据管理；模型架构和生成任务独立实现。
