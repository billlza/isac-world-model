# 第三项实验：恢复画面、旧事件和训练种子

前序：Hamilton 作业 19341792，提交 b2547848b09b8c8cb3e7a03ce0154595465006d6。A96 指有显式事件检索、隐藏宽度 96 的 structured-attention，共 172,246 个参数。本次不改变模型宽度。两阶段在同一张完整 H200 NVL 上依次运行，合计申请上限 60 分钟。源运行只读；本目录不是结果声明。

## 1. 原权重上的干预

利用 3 个训练种子、两种宽度、两种结构的 12 个原始最佳检查点。先按用户留存的证据核对 3 份训练说明、6 份评分、12 份模型文件的 SHA-256。核对同一设备运行所需的版本、原训练和验证轨迹集，以及 24 对挑战轨迹的观测日程。每个模型、每个场景在未干预分支都须复现原始 11 点恢复曲线，逐点容差 0.0002 m；恢复标记和确认时刻要求一致。不通过就保留失败状态，不启动第二阶段。

模型在收到第一条恢复画面前的状态只计算一次。所有分支从它的副本起步。四种模型均比较正常供给相机和扣住恢复后拍摄的所有相机包；RF、真实运动和评分时钟保持不变。A96 另做两种检索条件，在处理第一张恢复画面之前一次性将事件库内旧键标为不可见；空键、递归状态、显式位置与协方差、后续包括当次的新写入都保留。这里隔离的是重新读取送达前旧事件的增量作用，不是抹掉模型记住的一切。此前从轨迹开头起的历史效应已经包含在共同分叉状态里。被扣住的是这段期间所有恢复画面，不能读成只改变了第一张画面。

原测试集作为诊断重放。三份 A96 各评估 24 对直行 / 转向场景，各四个分支；其余九份各两个分支。输出键 `camera_on/off_oldkeys_on/off`。配对收益统一计算为 **扣住时的误差积分 − 正常供给时的误差积分**，正数表示供给该信息有帮助。交互使用“保留旧键时的相机收益 − 屏蔽旧键时的相机收益”，正数表示保留旧键让相机更有帮助。逐训练种子、分场景报告，另保存送达前误差、恢复曲线、连续达标与末端再次超界的记录。主要终点仍是 1 秒欧氏位置误差梯形积分，m·s；除以 1 秒才能解释为这段时间的平均误差。

## 2. 初始化 × 训练轨迹

仅训练 A96。四个格子为 (初始化, 训练数据块) = (7,7)、(7,11)、(11,7)、(11,11)。数据块分别为从 700000 和 1100000 开始的各 96 条轨迹；每条 64 步。统一使用 12 条验证轨迹 73511000–73511011；固定 minibatch 顺序种子 37、batch 8、16 epochs、每模型 192 次更新。四个模型都重新训练（无预训练权重）；原本两个同号组合的验证集与训练顺序不同，不能代替新对照。先保存 4 个独立选择的最佳检查点，再测试。

24 对旧挑战仅供对照复现；预先保留的新测试为 94761000–94761023，两种运动条件与前序协议相同，新测试轨迹不做调参或模型选择。记录每个格子的绝对误差、与 KF／门控 IMM 的比较、条件化的初始化效应、数据效应及交互。配对区间按轨迹抽样，条件为这两个初始化和这两个数据块；不是对任意训练种子的方差分解。更换公共验证集和批次顺序后，即使两因素都拆开，历史特定运行的所有差距也不一定会重现。若未复现，应如实报告。

## 3. 提交与取结果

同一提交的发起器仅提交一次。使用 Mac 本地已有项目目录，核对完整 Git SHA 后通过 Bash 运行 `scripts/submit_memory_followup_from_mac.sh <完整SHA> <学校短用户名>`。需保留上一项研究在 Hamilton 的工作树和 12 份模型。发起器自动用原学校 Python 模块；新作业只写入独立结果目录，不更动 19341792 的成果。

提交后终端会打印真实作业号和查询命令。PENDING 表示仍在排队；RUNNING 时可查看该作业的 status.json 或 Slurm 日志。完成后用终端打印的 scp 命令下载一个 isac-memory-作业号.tar.gz。内含完整冻结重放、逐种子和逐轨迹结果、交叉训练记录以及 readout.json；模型仍留在学校。中途失败请查看状态里的 stage，保留输出，不自动重复提交。
