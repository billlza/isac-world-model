## 本版修补的具体问题

### 1. 将因果性与数值一致性分开验证

重新执行旧版测试得到 86 项通过、1 项失败。未来帧的有效掩码改变了批量编码规模，早期输出出现约 1e-8 的浮点差异；这不是直接证明模型读取了未来，但旧的严格前缀测试确实不通过。

本版逐步评测默认采用前缀稳定编码；训练显式启用批量编码。测试同时覆盖：未来数据/掩码变化不影响早期输出、未来输入梯度为零、批量与逐步路径的数值及梯度一致性。没有通过删除测试或直接放宽原断言来报绿。

### 2. 计算不再只是一列耗时

`reference` 保留原瞬时逻辑供对照。`fixed` 指定推理工作者服务时间；`measured` 将当前主机测得耗时用于虚拟时间诊断。

工作者忙碌期间传感器仍采集；结果完成前不发布、不执行其感知指令。感知资源在指令真正执行的 tick 计费，随后才采集对应无线观测。已完成结果使用显式匀速/协方差模型传播至当前输出时刻。

有界队列采用显式 drop-new 策略，丢弃 ID 记录在轨迹；无已完成输出时状态为 `no_output`。每个任务记录输入截止时刻、最大输入可用时刻、完成与发布时间、请求/执行操作，支持审查。

默认 dt=100ms，发布向上量化到下一 tick。50ms 与100ms等配置可能具有相同离散效果，本模型不是精细 OS/GPU 排队器。measured 模式依赖主机负载，不用于可移植校准。

### 3. 校准、输入和产物边界

校准 schema v2 绑定运行协议、延迟、队列和协方差传播参数；旧 schema 只适用于 reference。更改条件后拒绝套用旧校准，不把未知条件继续标为可信。

增加有限数值/非布尔时间等输入验证；检查点对同一有界字节缓冲完成哈希及受限加载，避免哈希后替换路径；校验和文件大小/格式、ZIP 条目数量与展开规模受到约束。SHA-256 是完整性检查，不是身份认证，仍仅加载可信检查点。

Rust 批次写入先完整验证，失败不消耗 ID 或部分更新状态。CLI 限制行长和整数语法，非法输入可重复检验。

### 4. CI 不掩盖失败

每个检查有独立截止时间与日志；超时终止本脚本拥有的子进程组。缺工具返回2，失败返回1，全部选中检查通过才返回0。故障扫描任一场景失败都会返回非零，不能生成错误记录后仍报成功。

GitHub workflow 使用已核对的完整 Action commit SHA、只读权限、checkout 不保留凭据，无 privileged PR trigger；Linux/Python3.11与3.13、macOS/Python3.12 CPU、native、quality 和聚合 ci-gate。聚合门禁要求所有前提成功，不吞掉跳过/取消。是否阻止合并仍需在远端设置分支保护。

依赖是直接版本约束，不是完整传递依赖哈希锁；Ruff规则只覆盖致命正确性问题，不等于全面静态安全审计。本版没有声称漏洞数据库审计或内存安全的完整形式证明。

## 延迟敏感性实测（仿真）

使用上一版自己从零训练的 `checkpoints/v020.pt`，固定4条独立测试轨迹（seed 50000000–50000003），没有针对这些测试重新训练。下表是各轨迹RMSE的均值。

| 假设服务时间 | 卡尔曼＋固定策略 RMSE | 模型＋固定策略 RMSE | 固定策略实际感知比例 | 平均完成任务数 |
|---:|---:|---:|---:|---:|
| 0 ms | 0.2503 m | 0.3520 m | 10.00% | 48 |
| 50 ms | 0.3094 m | 0.3755 m | 9.79% | 47 |
| 150 ms | 0.4050 m | 0.7700 m | 4.79% | 23 |
| 300 ms | 0.7464 m | 1.3269 m | 3.13% | 15 |

这里的50/150/300ms是**指定的服务时间**，不是当前CPU或某款Mac的实测推理速度。慢计算改变结果与后续动作的可用时刻，任务频率和实际感知开销也会变化；不能把感知比例下降描述成没有代价的效率胜利。

本实验不提供校准，所以默认监测器不接受结果；接受比例为零不是可靠性已得到解决的证据。经典基线在这些条件下仍更准确。本版确立的是更真实的评测和因果执行，不是新模型精度突破。
