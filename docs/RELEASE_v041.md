# v0.4.1: explicit release and installation contracts

This release hardens reproducibility and first publication, without modifying the learned estimator.

## Required full checks

`--profile all` requires twenty checks, including the original tests/integration/lint/native/advisory
checks plus lock consistency, native toolchain identity and isolated install reproducibility.
`evidence.py` rejects partial profiles, missing/duplicate checks, changed source, missing logs,
altered evidence and paths escaping the report directory. The full CI report hashes top-level
logs and structured records. Large transient smoke checkpoints/replays are not required publication
evidence; they can be regenerated by the recorded integration commands. Hashes detect alterations,
not authenticate an author or certify an algorithm.

## Reproducibility scope

The install check starts with a new package cache and no system site-packages. It installs the
locked project non-editably into one new virtual environment, checks dependencies/import locations,
and trains a small random-initialized model. It repeats in a second new environment with uv's
`--offline` mode and the populated cache. Exact installed package/version inventories must match.
The two environments use the same selected CPython and host operating system. This is not an
OS/container bit-for-bit build or proof that Python/Rust installers work without network access.
Linux uses the explicitly pinned PyTorch CPU index; macOS uses the appropriate macOS wheel.
CUDA/MPS deployment measurements are separate, not inferred from CI or package resolution.

## Project-local toolchains

Bootstrap checks linker availability and an existing .venv before downloading. Python installs and
uv's cache now live under .toolchains as well as Rust. `bash scripts/env.sh <command>` restores
PATH/CARGO_HOME/RUSTUP_HOME/uv paths in later shells. No global Rust default or system interpreter
is modified. GitHub CLI is a separate publication tool using the user's own local login.

## GitHub first publication

The offline preflight restores Git metadata from the archive's history.bundle if needed, verifies a
passed full report against the actual source and checks a clean, complete commit. It never synthesizes
a commit that omits the lock file. `--execute` authorizes creation/push to billlza/<name> only.
An existing private repository is accepted only if empty or already exactly at the local main commit;
other refs/history are refused. It never force-pushes, makes a repository public or edits another repo.
Git authentication is scoped to individual git commands; it does not rewrite global credential helpers.

A receipt records repository URL, local/remote SHA, source digest, upload status, CI status, workflow
URL and all job conclusions. Upload verification checks the actual uv.lock, .python-version and
workflow bytes at the exact remote commit. CI waiting is bounded and requires every job including
ci-gate to complete successfully. Skipped/cancelled jobs and a green run on a different SHA fail.

On a creation/push error, fix local authentication/permissions then rerun; no new commit is needed.
On a CI failure, inspect the recorded workflow URL. After a deliberate source fix, create a new commit
and rerun full CI; the first-publication script refuses to overwrite existing different history.
Use normal reviewed git pushes for subsequent updates.

For a bundle-only checkout use `--report <path-to-current-full-ci-report>` after running bootstrap;
the source archive includes a release report for direct offline preflight.

## Tool boundary for this handoff

The conversation's connected GitHub account was confirmed as billlza; the target repository lookup
returned HTTP 404. The exposed connector supports writes inside existing repositories, but provides
no repository-creation operation. No GitHub upload or remote Actions success is asserted without a
receipt. Run the provided publisher locally with GitHub CLI to complete that external step.
